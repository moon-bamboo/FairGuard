# 检测器使用说明（抓"自动装车"）

> 这份是**给使用者看的**：怎么装、怎么确认它在工作、命中时看到什么、怎么调。
> 原理与判据的证据看 `00-项目总览.md` 第四节，实现细节看 `06-下一步-检测器设计.md`。

---

## 一、它做什么

在联机对局里**实时**发现对手用"自动装车"类插件，然后：

1. **屏幕上弹一句提示** —— 当场就能看到，不用等打完一局
2. **日志里记一行详情** —— 帧号、房号、几个单位配几辆不同载具
3. **带哈希链** —— 日志被事后改动会对不上（局限见第五节）

判据（**已由真实联机数据验证**）：

> 同一帧内，某玩家的一批 `MegaMission` 命令里，
> **「目的地不同取值个数」≈「发令单位不同取值个数」** → 自动装车。

**为什么这是"逻辑必然"**：让 10 个单位各进 10 辆**不同**载具，
玩家必须逐个点（点单位A → 点载具A → 点单位B → 点载具B……）共 20 次点击，
**人手不可能压进同一帧**（一帧约 1/60 秒）。插件一次下发就能。

实测对照：手动进同一辆 = 1；手动 PvP 技巧进两辆 = 2；**自动装车 10 配 10 = 10**。
**1 和 10 之间没有模糊地带。**

## 二、部署

把这三个文件放进**游戏根目录**（`gamemd.exe` 所在的那一层）：

```
EventProbe.dll          <- 插件本体（探针 + 检测器）
EventProbe.dll.inj      <- 钩子声明（文件名必须与 DLL 完全一致）
EventProbe.ini          <- 配置
```

启动游戏后日志写在：

```
<游戏目录>\MsgLog\EventProbe_日期_时间.log
```

> ⚠️ **只要自己装**。对手不用装任何东西 —— 判据用的数据是所有玩家
> （含远程）的命令队列，每个客户端本来就有。
>
> ⚠️ 装了 **ChatBox** 的话，屏幕提示会显示在 ChatBox 的消息窗里；没装就显示在
> 原版消息区（和"结盟提示""快捷键提示"同一个位置）。

## 三、先确认它在工作

打开日志，**开头**应该有这几行：

```
EventProbe 1.1 start
config: Enable=1 DumpRaw=0 ...
detector: Enable=1 MinEvents=5 MinDest=5 RatioPercent=50 ShowAlert=1 ...
addr: DoList=<008B41F8> OutList=<00A802C8> CurrentFrame=<00A8ED84> AddMessage=<005D3BA0>
hash-chain: sha256, initial=<64位十六进制> (each DETECT line carries chain=...)
```

再看有没有心跳：

```
hook: frame alive (0x55D360), CurrentFrame=...
hook: ExecuteEventsHook #1 entered, frame=0
```

| 现象 | 含义 |
|---|---|
| 连 `start` 都没有 | DLL 没被加载 → 看 Syringe 日志里有没有 `Recognized DLL` |
| 没有 `frame alive` | 帧钩子地址有问题（不太可能，那是多方共用的老钩点） |
| 只有 `start` 没有 `ExecuteEventsHook` | 主取样钩子没被调到 |
| `detector:` 那行 `Enable=0` | 检测器被配置关掉了 |

**对局中**每 60 帧会有一行队列状态（探针的），里面 `in=` 是队列深度：

```
list: f=1920 in=5/10 out=2/3 calls=959 maxOps=3@h0 | e0 t=1C h=1 fr=1920 ex=0
```

**⚠️ 单机时 `in=0/0` 是正常的** —— 单机不产生事件队列（那套机制只为网络同步存在），
所以**单机永远看不到检测结果，必须联机**。

## 四、命中时看到什么

### 4.1 屏幕提示

```
【可疑】检测到自动装车特征：房号1 第26004帧 10 个单位配 10 辆不同载具
```

10 秒内在滑动窗口里再次命中会变成：

```
【可疑·重复】自动装车特征：房号1 第26548帧 10 个单位配 10 辆不同载具（2 次重复）
```

> `房号` 是引擎里的玩家槽位编号，**不一定**等于"玩家1/玩家2"。
> 哪个房号是哪台机器，要从日志里核对（别靠"谁消息多"猜 —— 这是踩过的坑）。

### 4.2 日志里的命中行

```
*** DETECT f=26004 h=1 units=10 veh=10 MM=10 (Move=0 Enter=10) ratio=100% chain=1A2B3C4D5E6F7081
*** DETECT-REPEAT f=26548 h=1 hitsInWindow=2/600 frames, totalHits=2
```

| 字段 | 含义 |
|---|---|
| `f=` | 逻辑帧号 |
| `h=` | 房号（哪个玩家） |
| `units=` | 这批命令涉及几个**不同**的发令单位 |
| `veh=` | 这批命令打给了几辆**不同**的载具 ← **判据的核心数字** |
| `MM=` | 这一帧该玩家的 `MegaMission` 有效条数 |
| `(Move=/Enter=/Other=)` | 其中的 Mission 分布（`02`=Move，`07`=Enter） |
| `ratio=` | `veh / units` 的百分比（100% = 严格一对一） |
| `chain=` | 哈希链当前值的前 8 字节 |
| `invalid=` | 字段还没算出来的条数（出现时不影响判据，只是不参与统计） |

### 4.3 汇总行

```
[DETECT] alive f=24000 hits=2 scans=812 frames=24000 chain=1A2B3C4D byHouse=h1:2 recs=2
[DETECT-SUMMARY] ver=1.1 f=74000 hits=2 scans=1904 firstHit=26004 lastHit=26548 byHouse=h1:2 chain=<完整64位> recs=2
```

| 字段 | 含义 |
|---|---|
| `hits=` | 这一局累计命中次数 |
| `scans=` | 出现过有效命令的帧数（**活性指标**：它不涨说明没数据） |
| `byHouse=` | 按房号的命中次数 |
| `chain=` | 哈希链最终值（`SUMMARY` 行给完整 64 位） |
| `recs=` | 链里累计录入了多少条记录 |

- `[DETECT]` 每 1800 帧（约 30 秒）在**有新命中时**输出一次
- `[DETECT-SUMMARY]` 在**退出游戏**时输出一次（中途退回主菜单不会触发，所以有上面那个兜底）

### 4.4 原始字节（`LogRaw=1` 时）

```
detraw f=26004 h=1 i=0 | 04 00 01 94 65 00 00 6D 3E 10 00 34 07 06 00 00 00 00 00 1D DF 00 00 0B
```

每条 24 字节（覆盖到目的地）。用于人工复核判据 —— 能直接看出
`Whom`（偏移 7..11）、`Mission`（12）、`Destination`（19..23）各不相同。

## 五、配置（`EventProbe.ini`）

### 最常用的四项

| 项 | 默认 | 说明 |
|---|---|---|
| `[Detector] Enable` | `1` | 检测器总开关 |
| `ShowAlert` | `1` | 屏幕上弹提示；做对照实验时可设 `0` |
| `MinEvents` / `MinDest` | `5` / `5` | 规模门槛。调小 → 能抓小规模装车，但更易误报 |
| `RatioPercent` | `50` | `veh` 至少要到 `units` 的百分之几 |

### 全部配置

见 `EventProbe.ini`，每一项都有中文注释。容易误解的三个：

- **`WindowFrames` / `WindowHits`**（默认 `600` / `2`）：约 10 秒内命中第 2 次就升级为
  "重复"告警。想只报一次就设 `WindowHits=9999`。
- **`IgnoreHouses`**（默认空）：要排除的房号，逗号分隔（如 `3,5`）。
  联机遭遇战里**电脑玩家(AI)也有自己的房号**，AI 可能成批下发命令；
  如果发现某个房号总是误报且确认那是 AI，就在这里排除它。
  ⚠️ 排除了就真的看不到了，别把真人玩家的房号写进去。
- **`HashChain`**（默认 `1`）：日志防篡改。局限见下节。

### 想关掉检测器、只当探针用

```ini
[Detector]
Enable=0
```

探针的统计输出照常（由 `[EventProbe] Enable` 独立控制）。反过来也一样：
`[EventProbe] Enable=0` + `[Detector] Enable=1` 时，只输出检测告警，不输出逐帧统计。

## 六、⚠️ 边界与局限（务必知道）

### 6.1 单机没有数据

单机时 `DoList.Count` 每帧都是 0 —— **必须在联机对局里才有效**。
（原理见 `01-技术方案.md` 第五节。）

### 6.2 本机事件与对手事件的差别

实测（`01-技术方案.md` 第六节）：同一条事件在两台机器上，**偏移 13 起有差异**
（本机读到的时刻更早，部分字段还没算完）。

- **对手的事件**（远程同步过来的）：字段完整 → **一定能检测** ✓
- **自己本机的事件**：取样瞬间部分字段可能还没填好

⇒ **检测器天生就是用来抓对手的。** 想用它验证自己本机操作时要注意这一点，
见第七节的测试步骤。

### 6.3 只能发现"行为异常"，不能证明"对方装了插件"

插件产生的命令与玩家点击产生的命令**字节级同构**（AutoLoad 的源码注释自己写明了）。
所以本工具输出的是**可疑度报告**，最终判断由人来做。

### 6.4 温和使用检测不到 / 可以规避

- 一秒装一次、慢慢的，与手速快的玩家无法区分
- 加随机延迟、改走别的命令路径，特征就没了
- 单帧只装 2~3 个，低于 `MinDest` 阈值也不报（除非你把阈值调小）

### 6.5 哈希链只防"事后修改"

- 防不住**整份重新生成**（算法公开、无密钥）
- **单人日志无法自证**，要成为有效证据需要**多方交叉核对**
- 所以只对**事件头部 +0..+12** 做哈希：目的地之后的字节在不同机器上不一样
  （那是本地状态），整条哈希无法交叉验证

**多方交叉核对的可行性已被实测支持**：那台"没有操作"的机器，
完整记录下了对方的每一个操作事件，且**事件头部两台完全一致**。

## 七、实机测试步骤

> ⚠️ 每一步之间**间隔 10 秒以上**，方便在日志里按时间切开。

### 阶段 A · 确认插件活着（单机即可）

1. 部署三个文件，启动游戏（原版或 MO）
2. 开一局遭遇战（单机也行）
3. 退出，看日志开头有没有 `start` + `detector:` + `frame alive`
4. 单机时 `list:` 行显示 `in=0/0` 是**正常的**

### 阶段 B · 用"手动操作"确认不误报（联机，最重要）

两台机器联机，**只有你操作**：

| 编号 | 动作 |
|---|---|
| **A** | 框选 **5 个兵** → 点**一辆**运输车（手动装车），等 10 秒 |
| **B** | 框选 **5 个兵** → 点地面（普通移动），等 10 秒 |
| **C** | 用 PvP 技巧装**两辆**（进载具A + 路径点 + 进载具B），等 10 秒 |
| **D** | 框选 10 个单位 → 点一辆载具，等 10 秒 |

**期望：一次 `*** DETECT` 都没有。**
（日志里会有 `evt` 行和 `BURST` 行 —— 那是探针的粗略统计，不是判据告警。）

### 阶段 C · 用 AutoLoad 确认能抓到（联机）

这次让**对手那台**装上 AutoLoad（或者你在自己机器上装，但要装探针在**另一台**上看）：

| 编号 | 动作 |
|---|---|
| **E** | 对手选中 **10 个单位 + 10 辆载具**，按 **Ctrl+D** 自动装车，等 10 秒 |
| **F** | 重复 2~3 次，每次间隔 10 秒 |

**期望**：出现 `*** DETECT ... units=10 veh=10 ... ratio=100%`，
并且第 2 次起伴随 `*** DETECT-REPEAT`，屏幕上弹出中文提示。

**取日志时优先用"没有操作的那台"的日志**（字段更完整，见 6.2）。

### 阶段 D · 把日志发给我

日志位置：`<游戏目录>\MsgLog\EventProbe_*.log`

> ⚠️ `E:` 盘在沙箱里只读，工具**不能**直接读游戏目录 —— 需要手动复制出来。

**重点回答三个问题**：
1. 阶段 B 有没有误报？（有没有出现 `*** DETECT`）
2. 阶段 C 抓到了几次？`units` / `veh` 是多少？
3. 单机自测（本机装 AutoLoad + 本机装探针）能不能抓到自己？

第 3 点是要确认的事：本机事件在取样瞬间目的地字段是否已经填好。
对手的事件一定完整，本机的**需要实机确认**。

## 八、它和探针的关系

同一个 DLL 里两件事，共用同一个取样钩子（`0x64C38D` + `0x55D360`）：

| | 探针 `[EventProbe]` | 检测器 `[Detector]` |
|---|---|---|
| 目的 | 校准地址、收基线、诊断 | 实时抓自动装车 |
| 输出 | `evt` / `raw` / `list` / `BURST` 行 | `DETECT` / `DETECT-REPEAT` / `DETECT-SUMMARY` 行 + 屏幕提示 |
| 默认 | 开 | 开 |

**为什么合成一个 DLL**：两者都要钩同样的两个地址。
Syringe 对**同一地址**的多次 hook 是后装覆盖先装 ——
两个 DLL 各钩一次，必然有一个哑掉甚至崩溃。合在一个 DLL 是唯一稳妥的做法。

```bat
cd src

gcc -O2 -Wall -o test_abi.exe      test\test_abi.c               :: 调用约定：5 项
gcc -O2 -o test_load.exe test\test_load.c -lkernel32             :: 加载自检
```
