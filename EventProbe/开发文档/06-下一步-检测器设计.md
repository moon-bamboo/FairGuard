## 一、目标

在联机对局中**实时**发现对手使用"自动装车"类插件，并留下可追溯的记录。

**不属于本项目范围**（用户已明确或已排除）：
- 检测"是否加载了某个 DLL" —— 技术上不可能（DLL 注入不改 exe）
- 判断"某条命令是不是插件发的" —— 单条命令与手动点击**字节级同构**
- 画面录制 / 回放

## 二、判据的实现

### 2.1 数据来源

`EventClass::DoList @ 0x008B41F8`（环形队列，见 `01-技术方案.md`）。

**每个逻辑帧**遍历一次，筛选条件：

```
event[0]  == 0x04                    // Type == MegaMission
event[1] & 1 == 0                    // 未执行
event[2]  == 房号                     // 按玩家分桶
event[3..6] == CurrentFrame          // 目标帧 == 当前帧
```

### 2.2 提取字段

| 偏移 | 含义 |
|---|---|
| `[7..11]` | `Whom` —— 发令对象（`TargetClass`：ID(4) + RTTI(1)） |
| `[12]` | `Mission`（`02`=Move，`07`=Enter） |
| `[19..23]` | `Destination` —— 目的地（载具） |

### 2.3 判定逻辑（伪代码）

```c
for (每个房号 h) {
    whomIds[32];  int nWhom = 0;      /* 去重后的 Whom ID 集合 */
    destIds[32];  int nDest = 0;      /* 去重后的 Destination ID 集合 */
    int nEvt = 0;

    for (该帧属于 h 的每条 MegaMission) {
        nEvt++;
        addUnique(whomIds, &nWhom, WhomID(e));
        addUnique(destIds, &nDest, DestID(e));
    }

    /* ★ 判据：每个单位配一辆不同载具 */
    if (nEvt >= MIN_EVENTS && nDest >= MIN_DEST && nDest * 2 >= nWhom)
        告警(h, nEvt, nWhom, nDest);
}
```

### 2.4 阈值建议

| 配置项 | 建议默认 | 说明 |
|---|---|---|
| `MIN_EVENTS` | `5` | 本帧该玩家的 `MegaMission` 至少这么多条 |
| `MIN_DEST` | `5` | `Destination` 至少这么多个**不同**取值 |
| 多样性比例 | `nDest * 2 >= nWhom` | 允许一部分单位进同一辆（宽容） |

**依据**（见 `03-实测数据与判据验证.md`）：

| 场景 | `nDest` |
|---|---|
| 手动：多单位进同一辆载具 | **1** |
| 手动：PvP 技巧（两辆） | **2** |
| **自动装车：10 单位配 10 辆** | **10** |

**1 与 10 之间没有模糊地带**，阈值只需让"小规模自动装车"也能被捕捉。

### 2.5 可选增强（防止漏检）

单看一帧可能漏（`Execute_DoList` 在联机时约一半的帧被调用，采样会漏帧）。
可再加一层**滑动窗口**：

```
统计最近 N 帧（比如 60 帧 = 2 秒）内，该玩家命中的"可疑帧"次数
若 >= M 次 → 升级告警
```

**证据**：用户 f 步骤（AutoLoad 重复 2~3 次）在日志里表现为
`16:32:00` 与 `16:32:08` 两次命中，间隔 8 秒。

## 三、检测器功能设计

### 3.1 要输出的三层信息

| 层 | 内容 |
|---|---|
| **实时提示** | 屏幕上显示一行警告（"疑似自动装车：玩家X 帧N 10单位/10载具"） |
| **详细日志** | 每次命中记录：帧号、房号、事件数、Whom/Destination 去重数、原始字节 |
| **汇总** | 一局结束或按热键时输出：总命中次数、按玩家统计 |

### 3.2 配置项草案

```ini
[Detector]
Enable=1
MinEvents=5          ; 单帧最少 MegaMission 条数
MinDest=5            ; 单帧最少 Destination 不同取值数
RatioPercent=50      ; nDest 至少要达到 nWhom 的百分之几
ShowAlert=1          ; 是否在屏幕上显示
AlertSeconds=10      ; 提示停留时间
LogRaw=0             ; 是否记录命中帧的原始字节
```

### 3.3 屏幕提示的实现参考

**同工作区的 `ChatBox` 插件**已经有现成的绘制代码（半透明底板 + 引擎文本绘制），
可以直接参考，不必从零写：

| 用途 | ChatBox 里的实现 |
|---|---|
| 半透明底板 | `FillRectTransVt()`（虚表 `+0x1C`） |
| 文本绘制 | `Fancy_Text_Print_Wide` 的 ColorScheme 重载 `0x4A61C0`（**`__cdecl`，8 参数**） |
| 每帧钩子 | `0x55D360` |
| 引擎帧号 | `0xA8ED84` |

**⚠️ 也可以在屏幕上不画**，只写日志 —— 更简单，且不容易与别的插件冲突。

### 3.4 日志防篡改（用户明确提过）

**做法**：哈希链

```
chain = SHA256(chain || 房号 || 帧号 || 事件数 || nWhom || nDest || 时间戳)
```

局末输出摘要：

```
[DETECT-SUMMARY] ver=1.0 hits=3 chain=A3F2C891...
```

**⚠️ 必须说清的局限**（用户已经理解并接受）：
- 只能防**事后修改**，防不住**整份重新生成**（算法公开、无密钥）
- 单人日志**无法自证**；要成为有效证据需要**多方交叉核对**
- 加固点：**只能对事件头部（`+0..+12`）做哈希** ——
  `Destination` 之后两台机器不一样（本地状态），见 `01` 第六节

**多方交叉验证的可行性已被实测支持**：那台没有操作的机器，
完整记录下了对方的每一个操作事件，且**事件头部两台完全一致**。

## 七、实现时的关键决定（给接手的人）

### 7.1 为什么不新建一个"检测器 DLL"，而是并进 EventProbe

两者都要钩 `0x64C38D` / `0x55D360`。Syringe 对**同一地址**的多次 hook 是
后装覆盖先装 —— 两个 DLL 各钩一次，必然有一个哑掉甚至崩溃。合在一个 DLL 是唯一稳妥做法。

配置上仍分两段（`[EventProbe]` / `[Detector]`），可以分别开关。

### 7.2 屏幕提示为什么**不自己画**

ChatBox 那套"接管绘制"的做法在别的插件已占 `0x4F4558` / `0x5D4A94` 的前提下会冲突。
改用引擎自己的消息入口 `MessageListClass::AddMessage`：

- 不占绘制钩点，与 ChatBox 天然共存（装了 ChatBox 就显示在它的消息窗里）
- 颜色/字体/折行全由引擎处理
- 纯本地 UI 消息，不进事件队列，不影响 lockstep

**调用约定是这里唯一的风险点**（`__thiscall`：ECX=this + 7 个栈参数 + `ret $0x1C`，
用 GCC 的 `__fastcall` 表达）。所以专门写了 `test/test_abi.c`，
用一个真正的 `__thiscall` 函数接收并逐个核对 —— 见 `04-踩坑记录.md` 第 13 条。

### 7.3 只喂 `MegaMission(0x04)`，不含 `MegaMissionF(0x05)`

字段偏移只在 `0x04` 上实地校准过。`0x05` 的 `DataBuffer` 布局未必相同，
拿错位的字节去下结论比不做还糟。

### 7.4 命中的当口**不显示**，只登记

命中是在 `Execute_DoList` 内部（`0x64C38D` 钩子）算出来的，那一刻引擎正在消费事件队列。
在别人的函数中途调 UI 函数有重入风险。所以：
**命中处只登记 `PendingAlert`，由帧钩子 `0x55D360`（帧入口，安全时机）显示。**

### 7.5 字段为 0 的事件被剔除

实测：事件在**本机刚生成**的那一瞬间，`Destination` 等字段还没算出来，读到全是 0。
若把 0 当作正常取值，会污染判据。所以 `Whom` 或 `Destination` 为 0 的条目
**不计入有效集**，另记 `invalid=` 计数（日志里可见）。

### 7.6 去重集合溢出时不再增长

容量 `DET_MAX_UNIQ = 64`，远大于实测规模（最大 20）。
真溢出说明数据异常 —— 此时"宁可不告警"也好过"拿截断后的集合下结论"。

## 八、实现对照（方案 → 代码）

| 方案里写的 | 实际落成 |
|---|---|
| 伪代码 `nDest * 2 >= nWhom` | 配置化成 `nDest*100 >= nWhom*RatioPercent`，默认 `RatioPercent=50` |
| `MIN_EVENTS=5` / `MIN_DEST=5` | `MinEvents` / `MinDest`，默认同值 |
| "同一帧、同房号的 MegaMission 集合" | `g_Det[16]`（每房号一份 `DetStat`），帧内 `DetStat_Feed` |
| 滑动窗口"最近 N 帧内命中 M 次" | `WindowFrames=600` / `WindowHits=2`，命中即 `*** DETECT-REPEAT` |
| 哈希链 `SHA256(chain ‖ 房号 ‖ 帧号 ‖ 事件数 ‖ nWhom ‖ nDest ‖ 时间戳)` | `ChainPush()`：另加 `nHeads`/累计命中数，并把**命中事件头部 +0..+12** 一并哈希（`06` 第 3.4 节要求） |
| 配置项草案 `[Detector]` | 全部实现，另加 `IgnoreHouses` / `SummaryEvery`；键名见 `EventProbe.ini` |
| "屏幕提示的实现参考 ChatBox" | **没有**参考它的绘制代码 —— 改用 `AddMessage`（理由见 7.2） |
