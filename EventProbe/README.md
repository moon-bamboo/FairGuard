# 对方玩家异常操作检测

检测《尤里的复仇》**联机对局**中，其他玩家是否使用了影响平衡的插件（主要是"自动装车"）。

## 一、快速开始

把这三个文件放进**游戏根目录**（`gamemd.exe` 所在的那一层）：

```
EventProbe.dll          <- 插件本体（探针 + 检测器）
EventProbe.dll.inj      <- 钩子声明（文件名必须与 DLL 完全一致）
EventProbe.ini          <- 配置
```

启动游戏、联机打一局。日志写在：

```
<游戏目录>\MsgLog\EventProbe_日期_时间.log
```

**最先确认三件事**（日志开头）：

```
EventProbe 1.1 start
detector: Enable=1 MinEvents=5 MinDest=5 RatioPercent=50 ShowAlert=1 ...
hook: frame alive (0x55D360), CurrentFrame=...
```

> ⚠️ **只需要自己装**。判据用的数据是所有玩家（含远程）的命令队列，
> 每个客户端本来就有 —— 对手不用装任何东西。
>
> ⚠️ **单机没有数据**：那套事件队列只为网络同步存在，单机时恒为空。
> **必须联机**才能看到结果。
>
> ⚠️ 屏幕提示走引擎自己的消息通道，所以**装了 ChatBox 就显示在 ChatBox 的消息窗里**，
> 没装就显示在原版消息区（和"结盟提示""快捷键提示"同一个位置）。

## 二、检测器：它是怎么抓的

### 判据

> 同一帧内、同一玩家的一批 `MegaMission` 命令里，
> **「目的地(Destination) 的不同取值个数」≈「发令单位(Whom) 的不同取值个数」**
> → 判定为自动装车

### 为什么这是"逻辑必然"，不是拍脑袋

要让 10 个单位各自进入 **10 辆不同**的载具，玩家必须**逐个**操作：

```
点单位A → 点载具A → 点单位B → 点载具B …… 共 20 次点击
```

**人手不可能把这些压进同一帧**（游戏一帧约 1/60 秒）。
而自动装车能在一帧内完成，因为它一次性给 10 个 (单位, 载具) 对下发命令。

### 实测对照（来自真实联机测试）

| 操作 | `Destination` 唯一值 |
|---|---|
| 手动：多单位进**同一辆**载具 | **1** |
| 手动：PvP 技巧（进载具A + 进载具B） | **2** |
| **自动装车：10 单位配 10 辆** | **10** ← 特征明显 |

**1 与 10 之间没有模糊地带，也不需要调阈值。**

### 命中时你会看到

**屏幕上**弹一句（停留 10 秒）：

```
【可疑】检测到自动装车特征：房号1 第26004帧 10 个单位配 10 辆不同载具
```

**日志里**记一行：

```
*** DETECT f=26004 h=1 units=10 veh=10 MM=10 (Move=0 Enter=10) ratio=100% chain=1A2B3C4D5E6F7081
*** DETECT-REPEAT f=26548 h=1 hitsInWindow=2/600 frames, totalHits=2
[DETECT-SUMMARY] ver=1.1 f=74000 hits=2 scans=1904 byHouse=h1:2 chain=<完整64位> recs=2
```

`units` = 几个单位，`veh` = 几辆**不同**载具 ← **判据的核心数字**。

> `房号(h)` 是引擎里的玩家槽位编号，**不一定**等于游戏里的"玩家1/玩家2"，
> 要从日志里核对。

### 常改的三个配置（`EventProbe.ini`）

| 项 | 默认 | 说明 |
|---|---|---|
| `[Detector] Enable` | `1` | 检测器总开关 |
| `ShowAlert` | `1` | 屏幕提示；做对照实验时可关掉 |
| `MinEvents` / `MinDest` | `5` / `5` | 规模门槛。调小 → 能抓小规模装车，但更易误报 |
| `RatioPercent` | `50` | `veh` 至少要达到 `units` 的百分之几 |

其余（滑动窗口、哈希链、忽略房号、汇总间隔）见 `EventProbe.ini` 里的中文注释。

## 三、⚠️ 已知局限（务必知道）

1. **单机没有数据** —— 必须联机。
2. **只能发现"行为异常"，不能证明"对方装了插件"**。
   插件产生的命令与玩家点击产生的命令**字节级同构**（AutoLoad 的源码注释自己写明了）。
   所以本工具输出的是**可疑度报告**，由人来判断。
3. **温和使用检测不到** —— 一秒装一次慢慢来，与手速快的玩家无法区分。
4. **可以规避** —— 加随机延迟、改走别的命令路径，特征就没了。
5. **哈希链只防"事后修改"** —— 防不住"整份重新生成"（算法公开、无密钥）。
   单人日志**无法自证**；要成为有效证据需要**多方交叉核对**。
   所以只对事件头部（`+0..+12`）做哈希 —— 目的地之后两台机器不一样（本地状态）。
6. **只读，不影响同步** —— 插件只读 `DoList`，不写任何游戏状态、不发任何事件。
   因此只需自己安装，也不会造成不同步（和 ChatBox 同一个道理）。
7. **本机事件与对手事件有差别**（实测）：同一条事件在两台机器上，偏移 13 起有差异。
   对手的事件字段完整，**一定能检测**；本机自己的事件待实机确认。

## 四、原理（为什么这条路走得通）

《尤里的复仇》联机用 **lockstep（帧同步）**：所有玩家把操作打包成"命令"广播给每个人，
各客户端在**同一帧**执行同样的命令。引擎把这些待执行的命令放在一个全局队列里：

| 项 | 地址 / 值 | 说明 |
|---|---|---|
| `EventClass::DoList` | `0x008B41F8` | **所有玩家**（含远程）待执行的事件 |
| `EventClass::OutList` | `0x00A802C8` | 本机待发送的事件 |
| `Unsorted::CurrentFrame` | `0x00A8ED84` | 全局逻辑帧号 |
| 单条事件大小 | **111 字节** | `sizeof(EventClass)` |

每条事件的头部：

```
+0    EventType Type        操作类型
+1    bool      IsExecuted
+2    char      HouseIndex   ★ 哪个玩家发的
+3    uint32    Frame        ★ 这条命令在第几帧执行
+7    uchar[104] DataBuffer  具体参数
```

`MegaMission`（类型 `0x04`）里我们用到三个字段：

| 偏移 | 字段 | 说明 |
|---|---|---|
| `[7..11]` | `Whom` | 发令对象（ID 4 字节 + RTTI 1 字节） |
| `[12]` | `Mission` | `02`=Move，`07`=Enter |
| `[19..23]` | `Destination` | 目的地（载具） |

**只读，不影响同步**：插件只**读**这块内存，不写任何游戏状态、不发任何事件。
因此**只需自己安装**，也不会造成不同步（和 ChatBox 同一个道理）。

## 五、探针（调试用，可忽略）

同一个 DLL 里还带着开发阶段的**探针**，用来诊断"地址对不对 / 这一帧到底有没有数据"。
它输出的是逐帧统计，不是检测结论：

```
evt f=22364 q=14 n=11 | h0 ops=10 chat=0 proto=0 MM=10 | h1 ops=0 chat=0 proto=1
list: f=1920 in=5/10 out=2/3 calls=959 maxOps=3@h0 | e0 t=1C h=1 fr=1920 ex=0
*** BURST f=22364 h=0 ops=10  (MegaMission=10, Mission=7(Enter): 10)
```

| 字段 | 含义 |
|---|---|
| `evt` 行 | 有事件的帧，按房号分桶统计（`ops` 玩家操作 / `chat` 聊天 / `proto` 协议 / `MM` MegaMission） |
| `list` 行 | 每 60 帧一次的队列状态：`in`=队列深度，`out`=本机待发，`calls`=钩子调用次数 |
| `BURST` 行 | **粗略**告警：单帧操作数达到 `BurstOps`。它不看目的地，所以**不是**判据 —— 判据看 `DETECT` 行 |

**排查用**：`in` 长期为 0 → 这个环境没有事件（单机就是这样）；
`calls` 不增长 → 钩子所在函数压根没被调用。

想只当探针用：把 `[Detector] Enable=0`。

## 六、构建

```bat
cd src
build.bat
```

需要 32 位 mingw（`..\ToolsChain\w64devkit`）。产物 `EventProbe.dll` 会被复制到本目录。

> 注意：目录名是中文，32 位 gcc 在非 ASCII 路径下会找不到自己的库
> （`ld.exe: cannot find -lkernel32`），所以 `build.bat` 会自动把工具链和源码
> 暂存到 `%TEMP%`（纯 ASCII）里编译，再拷回来。

**自检**（不需要游戏，三个都应输出 `failures: 0`）：

```bat
gcc -O2 -Wall -o test_detector.exe test\test_detector.c -I src
test_detector.exe     :: 判据核心 37 项（用真实样本字节，含防误报/防漏报用例）

gcc -O2 -Wall -o test_abi.exe test\test_abi.c
test_abi.exe          :: 屏幕提示的调用约定 5 项

gcc -O2 -o test_load.exe test\test_load.c -lkernel32
test_load.exe         :: DLL 加载 / 导出 / Syringe 握手
```
