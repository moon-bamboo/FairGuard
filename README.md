# FairGuard —— 对手异常操作检测

在《尤里的复仇》**联机对局**里，识别**其他玩家**是否使用了影响平衡的插件
（目前落地的是"自动装车"这一类）。

> **只需要自己装** —— 判据用的是引擎自己广播给每个客户端的命令队列，
> 对手装不装都一样查得到。（这个项目原来叫 `EventProbe`，那是探针阶段的名字。）

**当前状态**：

| 阶段 | 状态 |
|---|---|
| 可行性调研 / 地址与字段校准 | ✅ 完成 |
| 探针（诊断用） | ✅ 完成 |
| 判据设计与验证 | ✅ 完成 |
| 检测器（实时判定 + 屏幕提示 + 哈希链日志） | ✅ 完成 |
| 第一轮实机验证 | ✅ 完成 —— **发现 1 处误报、1 处漏报**（见下） |
| **1.2 修正后的复测** | ⬜ **下一步** —— 需要你开 `TraceAll` 再打一局 |

## 一、快速开始

把这三个文件放进**游戏根目录**（`gamemd.exe` 所在的那一层）：

```
FairGuard.dll          <- 插件本体
FairGuard.dll.inj      <- 钩子声明（文件名必须与 DLL 完全一致）
FairGuard.ini          <- 配置
```

启动游戏、联机打一局。日志写在：

```
<游戏目录>\MsgLog\FairGuard_日期_时间.log
```

**最先确认三件事**（日志开头）：

```
FairGuard 1.3 start
config: Enable=0 DumpRaw=0 ...                    <- 探针默认关闭，日志因此很小
detector: Enable=1 MinEvents=5 MinDest=3 RatioPercent=0 MissionFilter=7 TraceAll=0
detector: ShowAlert=1 AlertSeconds=10 WindowFrames=600 WindowHits=2 HashChain=1 ...
hook: frame alive (0x55D360), CurrentFrame=...
```

对局中**每约 30 秒**会有一行"报活"。探针关掉之后，**这一行是唯一的活性指标**：

```
[DETECT] alive f=12600 hits=5 scans=177 frames=12601 byHouse=h0:5 chain=... recs=5
                         ^^^^^^^^^ scans = 取到过命令的帧数
                                   它在涨 = 事件队列有数据、检测器在正常跑
                                    一直是 0 = 根本没取到数据（单机？地址不对？）
```

> **关于日志体积**：探针（`[Probe] Enable=1`）会逐帧输出统计行，
> 实测一局 4.5 分钟就有 16,159 行 / 1 MB，其中 **96% 是探针的 `evt` 行**。
> 所以正式使用默认**关掉探针**，日志只剩检测器的告警与报活（约 1/25）。
> 需要排查时再打开 —— 见 `FairGuard.ini` 里 `[Probe] Enable` 的注释。

> ⚠️ **单机没有数据**：那套事件队列只为网络同步存在，单机时恒为空。**必须联机**。
>
> ⚠️ 屏幕提示走引擎自己的消息通道，所以**装了 ChatBox 就显示在 ChatBox 的消息窗里**，
> 没装就显示在原版消息区（和"结盟提示""快捷键提示"同一个位置）。

## 二、判据（1.2 修正版）

> 同一帧内、同一玩家的一批 **`Enter`（进入载具）** 命令里，
> **「目的地(Destination) 的不同取值个数」** 达到
> **`MinDest`（默认 3）** → 判定为自动装车

**为什么这是"逻辑必然"**：让 10 个单位各进 10 辆**不同**载具，玩家必须逐个点
（点单位A → 点载具A → 点单位B → 点载具B……）共 20 次点击，
**人手不可能把这些压进同一帧**（一帧约 1/60 秒）。插件一次下发就能。

**为什么不看"命令条数"**：手动框选 20 个单位点**一辆**车，同样是 20 条命令，
但目的地只有 1 个。**关键数字是"几辆不同的载具"，不是"多少条命令"。**

### ⚠️ 1.2 的重要修正：只能对 `Enter` 判定

第一轮实机测试暴露了一个**误报**：你"选中 20 个单位，进入路径点模式，移动到某个点"
时弹出了告警。

查日志发现 20 次命中**无一例外 `Enter=0`**：

```
*** DETECT f=10321 units=20 veh=10 MM=20 (Move=20 Enter=0 Other=0)
*** DETECT f=13823 units=20 veh=14 MM=20 (Move=0  Enter=0 Other=20)
```

原因：**不同的 Mission，`Destination` 的语义不一样**

| Mission | 目标是什么 | Destination 表现 |
|---|---|---|
| `2` (Move) | 一个**格子** | 路径点模式下引擎给**每个单位**展开各自的目标格 → 天然分散（20 个单位给出 10~14 个值）→ **会误报** |
| `7` (Enter) | 一辆**载具本体** | 手动装车不管框多少单位、点同一辆车 → 恒为 1；自动装车 10 配 10 → 10 ✓ |

所以检测器**只对 `Enter` 判定**（配置项 `MissionFilter`，默认 `7`）。

**代价**：如果某个装车插件改用 `Move` 实现，会漏掉它。实测那个插件（AutoLoad）走的是 `Enter`。

### 实测对照

| 操作 | `veh`（不同目的地数） | 判定 |
|---|---|---|
| 手动：多单位进同一辆载具 | 1 | 不报 ✓ |
| 手动：PvP 技巧（进两辆） | 2 | 不报 ✓ |
| 路径点模式移动 20 个单位 | 10~14（但 Mission 是 Move） | **不报**（被 `MissionFilter` 挡掉）✓ |
| 自动装车：20 单位配 3 辆 | 3 | **报** |
| 自动装车：10 单位配 10 辆 | 10 | **报** |

## 三、命中时你会看到

**屏幕上**弹一句（停留 10 秒）：

```
【可疑】检测到自动装车特征：房号1 第26004帧 10 个单位配 10 辆不同载具
```

**日志里**记一行：

```
*** DETECT f=26004 h=1 units=10 veh=10 MM=10 (Move=0 Enter=10) ratio=100% chain=1A2B3C4D5E6F7081
*** DETECT-REPEAT f=26548 h=1 hitsInWindow=2/600 frames, totalHits=2
[DETECT-SUMMARY] ver=1.3 f=74000 hits=2 scans=1904 byHouse=h1:2 chain=<完整64位> recs=2
```

| 字段 | 含义 |
|---|---|
| `units=` | 这批命令涉及几个**不同**的发令单位 |
| **`veh=`** | 打给了几辆**不同**的载具 ← **判据的核心数字** |
| `MM=` | 本帧该房号"参与判定"的命令条数（已过 MissionFilter） |
| `(Move=/Enter=/Other=)` | Mission 分布（**全部**命令，不受过滤影响） |
| `filtered=` | 被 MissionFilter 挡掉的条数 |
| `dup=` | 去重时遇到重复值的次数（正常现象，多个单位进同一辆车） |
| `chain=` | 哈希链当前值前 8 字节 |

> `房号(h)` 是引擎里的玩家槽位编号，**不一定**等于游戏里的"玩家1/玩家2"，要从日志核对。

### 漏报时怎么查：`TraceAll`

把 `[Detector] TraceAll=1` 打开，**没命中**但"命令量达到 `MinEvents`"的帧也会记一行：

```
trace f=13823 h=0 units=0 veh=0 MM=0 (Move=0 Enter=0 Other=20) ratio=0% filtered=20
```

- `filtered=20` → 这批命令的 Mission 不在 `MissionFilter` 里
- `veh=2` → 目的地还不够分散（可能真的是手动操作，或者插件是分帧下发的）

**这是回答"为什么没报"的唯一第一手材料。** 怀疑漏报时打开它，把日志发我。

## 四、常改的配置（`FairGuard.ini`）

| 项 | 默认 | 说明 |
|---|---|---|
| `[Detector] Enable` | `1` | 检测器总开关 |
| `MissionFilter` | `7` | **只对哪些 Mission 判定**。`7`=只判进入载具；`0`=不过滤（会误报路径点移动）；`2,7`=连移动一起判 |
| `MinEvents` | `5` | 单帧最少命令条数（低于此不判） |
| `MinDest` | `3` | **核心阈值**：至少几辆**不同**载具。2 不报（人力可为），3 起报 |
| `RatioPercent` | `0` | 比例条件，`0`=不检查。设 `50` = 至少要有"半个单位数"那么多的不同载具 |
| `ShowAlert` | `1` | 屏幕提示；做对照实验时可关 |
| `AlertThrottleSeconds` | `0` | 屏幕提示节流，**默认关闭**：同房号这么多秒内只弹一次。正常游玩用不到（曾经因为一次**测试时的**密集命中而默认开过）。**日志不受影响** |
| `TraceAll` | `0` | 诊断：漏报时打开 |
| `IgnoreHouses` | 空 | 要忽略的房号（AI 常在这里），如 `3,5` |

其余（滑动窗口、哈希链、汇总间隔、日志原始字节）见 `FairGuard.ini` 里的中文注释。

## 五、⚠️ 已知局限

1. **单机没有数据** —— 必须联机。
2. **只能发现"行为异常"，不能证明"对方装了插件"** —— 插件命令与玩家点击产生的命令
   **字节级同构**（AutoLoad 的源码注释自己写明了）。输出的是**可疑度报告**，由人判断。
3. **`MissionFilter` 是双刃剑** —— 只判 `Enter` 挡住了误报，但也意味着
   走 `Move` 实现的插件抓不到。
4. **分帧下发可能抓不到** —— 如果插件把 20 个单位分几帧、每帧只处理一辆车，
   那一帧看起来就和"手动框选一批点一辆车"一模一样。这也是要复测的原因。
5. **温和使用检测不到 / 可以规避** —— 一秒装一次、加随机延迟、改走别的命令路径。
6. **哈希链只防"事后修改"** —— 防不住"整份重新生成"（算法公开、无密钥）。
   单人日志**无法自证**，要成为证据需**多方交叉核对**。
   所以只对事件头部（`+0..+12`）做哈希 —— 目的地之后两台机器不一样。
7. **只读，不影响同步** —— 只读 `DoList`；屏幕提示走引擎本地消息通道，不进事件队列。

## 六、原理

《尤里的复仇》联机用 **lockstep（帧同步）**：所有玩家把操作打包成"命令"广播给每个人，
各客户端在**同一帧**执行同样的命令。引擎把这些待执行命令放在一个全局队列里：

| 项 | 地址 | 说明 |
|---|---|---|
| `EventClass::DoList` | `0x008B41F8` | **所有玩家**（含远程）待执行的事件 |
| 单条事件大小 | **111 字节** | `sizeof(EventClass)` |

每条事件的头部：`[0]`类型 `[1]`已执行 `[2]`**房号** `[3..6]`**帧号**
`[7..11]`Whom `[12]`**Mission** `[19..23]`**Destination**

**只读，不影响同步** —— 不写任何游戏状态、不发任何事件。

## 七、构建与自检

**从仓库根运行**：

```bat
src\build.bat
```

需要 32 位 mingw（同工作区的 `ToolsChain\w64devkit`，脚本会自己找）。
产物 `FairGuard.dll` 与 `FairGuardReport.exe` 会被放到仓库根。

`build.bat` 会自动"**编译 + 跑 4 个离线自检 + 落盘**"，**全部通过才算成功**
（任何一个不过就 `exit 1` 且不出产物 —— 别绕过它）：

| 自检 | 覆盖 |
|---|---|
| `test_detector` | 判据核心，63 项（含误报 / 漏报的回归用例） |
| `test_abi` | 屏幕提示的调用约定，5 项（含 2 万次调用的栈平衡） |
| `test_load` | DLL 加载 / 导出 / Syringe 握手 |
| `FairGuardReport --selftest` | SHA-256 标准向量 + 哈希链确定性 |

> 目录名是中文，32 位 gcc 在非 ASCII 路径下会找不到自己的库，
> 所以 `build.bat` 会把工具链和源码暂存到 `%TEMP%`（纯 ASCII）里编译，再拷回来。

**改过文档或配置之后**，再跑一次一致性审计：

```bat
powershell -NoProfile -ExecutionPolicy Bypass -File tools\check_docs.ps1
```

它会核对版本号、自检项数、文档里引用的文件是否存在、ini 键与代码是否对得上等
（细节见 `开发文档/README.md`）。

**打包发布**：

```bat
tools\make_release.bat
```

生成 `FairGuard-1.3.zip`（4 个必需文件 + 4 份文档），用于 GitHub Release。

## 九、下一步：复测（1.2）

具体步骤见 **`开发文档/07-检测器使用说明.md`** 第七节。要点：

1. **把旧的 `EventProbe.*` 三个文件从游戏目录删掉**，换成新的三个 `FairGuard.*`
2. 配置里 **`TraceAll=1`**（这一轮要看"没报出来的是什么样"）
3. 联机复现这几种操作，每种之间**间隔 10 秒**：

| 编号 | 操作 | 期望 |
|---|---|---|
| A | 路径点模式移动 20 个单位（**上一轮误报的那个**） | **不再弹提示** |
| B | 手动框选 20 个单位点**一辆**载具 | **不报** |
| C | 手动 PvP 技巧装两辆 | **不报** |
| D | 自动装车：20 个单位 + 3 辆 6 容量载具 | **应该报**（`veh=3`） |

4. 退出后告诉我一声 —— 日志在 `E:` 盘上，我读得到。

> 重点看 D：如果日志里 `trace` 行显示每帧 `veh=1`，那说明 AutoLoad 是**分帧下发**的，
> 这条路就走不通 —— 我会如实告诉你，不会硬凑一个判据出来。

## 十、打完一局之后：生成报告

日志是原始数据，不好读。把 `FairGuardReport.exe` 放进游戏根目录**双击**，
它会自动找最新那份日志，生成 HTML 报告并打开：

- **哈希链校验结论** —— 日志有没有被事后改动（改一处，后面全崩）
- **概览** —— 命中几次、哪些房号、每次涉及几辆**不同**载具
- **判据说明 + 怎么判断是不是误判** —— 报告里自带，不用翻文档
- **命中明细表** —— 时间、帧、房号、units、veh、链校验
- **效力边界** —— 为什么它只能当线索、不能当判决书

也可以**把某份日志拖到 exe 上**（只看那一份）。
加 `--no-open` 只生成不打开浏览器；`--selftest` 做自检。

**双机交叉核对**：把**两个**日志文件一起拖到 exe 上（或 `FairGuardReport.exe A.log B.log`），
它会按「同帧号 + 同房号」配对两份记录，报告**重合度**与**数值一致率** ——
这就是"多方交叉核对"的工具化。详见 `开发文档/07` 第 10.6 节。

**哈希链的诚实说明**：它能证明"日志内容与链自洽"，**不能**证明"这份日志来自
真实对局"（算法公开、无密钥，可以整份重造），也**不能**单独当证据 ——
要有效力需要**多方交叉核对**。详见 `开发文档/07` 第十节。
